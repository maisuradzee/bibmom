## Work performed

The four original sanitized GitHub Actions ZIP artifacts were downloaded from the workflow run and checked independently in a local Python process. For each ZIP, the ZIP SHA-256 was compared with the frozen summary and GitHub artifact metadata. The sole embedded JSON report was then extracted; its SHA-256 and byte length were compared with the frozen manifest.

For every one of the 192 method/layout/partition/worker cases, the three raw wall-time samples were used to recompute the median. The matching same-layout serial baseline was selected (`serial_naive` for naive threaded reduction; `serial_neumaier` for both Neumaier methods), and speedup was recomputed as `serial_median_wall_ns / threaded_median_wall_ns`. Accuracy counts and the CPU-time/wall-time threshold counts were also re-aggregated from raw case fields. Input-layout SHA-256 values were compared across all four runner/runtime cells.

## Reproduced results

- **FACT / REPRODUCED RESULT:** 4/4 ZIP digests and 4/4 embedded raw-report SHA-256/byte-length pairs matched the frozen summary.
- **REPRODUCED RESULT:** 192 configurations and 576 measured runs were recovered and re-aggregated.
- **REPRODUCED RESULT:** naive scalar `0/192`, scalar Neumaier `168/192`, full Neumaier `(sum, correction)` state `192/192` correctly rounded runs.
- **REPRODUCED RESULT:** CPU-time/wall-time ratio above 1.05 occurred in 4/288 GIL-enabled samples and 202/288 free-threaded samples.
- **REPRODUCED RESULT:** every runner/runtime/method median speedup was below 1.0. Full-state Neumaier medians were 0.733395 (Ubuntu GIL), 0.640091 (Ubuntu free-threaded), 0.837476 (macOS GIL) and 0.620236 (macOS free-threaded).
- **REPRODUCED RESULT:** both canonical input-layout SHA-256 values were identical across the four runner/runtime cells.

## Interpretation and limitations

The artifact set reproduces a numerical-accuracy result for the tested synthetic fixtures: full Neumaier state was correctly rounded in all 192 measured runs. Free-threaded runs frequently showed process CPU time exceeding wall time, consistent with concurrent CPU activity. That did **not** produce a wall-time speedup over the matching serial baseline in any of the four runner/runtime cells.

This is a reproduction of already-frozen hosted-runner artifacts, not a new benchmark, new physical-device experiment, or independent external replication. The two ARM64 runner families are GitHub-hosted environments; no bare-metal device, RSS/native-allocation measurement, DRAM hardware counter, energy measurement, representative production workload or external numerical-method review was added. `tracemalloc` remains a Python-allocation measure, not process RSS.
