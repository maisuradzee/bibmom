## Work completed

### NOEMA-007 — public source URL metadata guard

**Research question:** can public source metadata reject common credential-bearing URL forms before they enter a public research record, without fetching the source or blocking ordinary catalogue links?

**Implementation:** [PR #156](https://github.com/maisuradzee/bibmom/pull/156), branch `research/noema007-risk-baseline-freshness-evaluator-2026-11-27`.

- Added `_validate_public_source_url` using Python's `urllib.parse.urlsplit` and `parse_qsl`.
- Rejects URL user-info (username/password), known credential-like query and fragment keys, percent-encoded parameter names, control characters/whitespace, malformed ports and more than 100 parsed query/fragment fields.
- Normalizes parameter names before matching, so variants such as `access%5Ftoken`, `api-key` and `X-Amz-Signature` are covered.
- Allows ordinary public catalogue selectors such as `Links-sort=ResponsiblePerson-asc`.
- Does not fetch URLs, follow redirects, inspect remote content, prove publisher identity or authorize reuse.

**REPRODUCED RESULT:** four additional synthetic test methods cover user-info credentials, encoded query/fragment secret names, ordinary catalogue selectors, invalid ports and whitespace. Exact head `92ded19d5040631bbb73ba09fc4ee4df70f2254d` passed Quality CI [46009306236](https://github.com/maisuradzee/bibmom/actions/runs/46009306236) and CPU-thread workflow [46009306097](https://github.com/maisuradzee/bibmom/actions/runs/46009306097). Both workflow runs completed successfully; the Quality CI included the full Python suite, schema/reproduction checks and public site/publication-boundary build.

**FACT:** Python's standard-library documentation exposes parsed URL username/password components and query-pair parsing. It explicitly warns that `urlsplit()` does not itself perform URL validation. Source: https://docs.python.org/3.14/library/urllib.parse.html

**INFERENCE:** rejecting common credential-bearing URL forms reduces accidental disclosure risk when source metadata is committed to a public repository.

**HYPOTHESIS:** a source-metadata guard combined with repository secret scanning will reduce accidental publication of signed or credential-bearing URLs.

**UNTESTED IDEA:** compare the guard against a reviewed corpus of real public data-catalogue URLs and synthetic credential variants, with false-positive and false-negative analysis.

**Limitations:** this is a heuristic allow/deny check, not a complete secret scanner. Secrets can be embedded in path segments, opaque fragments, non-standard parameter names or other representations. It does not prove that a URL is safe, current, authoritative or reusable. No credentials or signed URLs were added to the repository.

### NOEMA-005 — complete Linux mountinfo path escape decoding

**Research question:** does the cgroup v2 resolver decode the complete character set used by the Linux kernel when it formats mount paths in `/proc/self/mountinfo`?

**Implementation:** [PR #157](https://github.com/maisuradzee/bibmom/pull/157), branch `research/noema005-cgroup-mount-root-resolution-2026-11-27`.

- Extended `_unescape_mount_field` to decode octal escapes for space (`\040`), tab (`\011`), newline (`\012`), hash (`\043`) and backslash (`\134`).
- Added regressions for newline and hash paths.
- Added escaped-backslash cases to ensure a literal sequence such as `\012` or `\043` is not decoded a second time.
- Preserved the existing segment-safe mount-root mapping and fail-closed capacity withholding.

**FACT:** the Linux kernel's `fs/proc_namespace.c` `mangle()` function passes space, tab, newline, backslash and hash to `seq_escape()`. The `seq_file` documentation specifies that `seq_escape()` emits escaped characters in octal form. Sources:
- https://github.com/torvalds/linux/blob/master/fs/proc_namespace.c
- https://docs.kernel.org/6.19/filesystems/seq_file.html
- https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html
- https://docs.kernel.org/6.19/admin-guide/cgroup-v2.html

**REPRODUCED RESULT:** deterministic unit tests exercise the pure path mapping and escaped-field decoder. Exact head `40d5bf9617f6ee6d6fc7b1d7da1748b1af429fe0` passed Quality CI [46009633734](https://github.com/maisuradzee/bibmom/actions/runs/46009633734), including the full Python suite, frozen-result checks, site build and publication-boundary checks.

**INFERENCE:** omitting newline or hash escapes can prevent a valid mount path from resolving. The current code now covers the path characters emitted by the inspected kernel formatter.

**HYPOTHESIS:** complete escape decoding will reduce false-negative cgroup path resolution in unusual mount namespaces.

**UNTESTED IDEA:** add a live mount-namespace integration test with synthetic mountinfo fixtures and a controlled temporary directory tree; separately compare the resolver with a trusted system parser such as libmount.

**Limitations:** no live mount namespace was created, no new timing diagnostic was run, and no physical x86-64/ARM64 benchmark was performed. The archived process-CPU/wall anomaly with maximum ratio 13.287713 remains unexplained; this parser change does not reproduce or explain it. No raw benchmark record was modified.
