### 1. NOEMA-007 — risk-baseline freshness evaluator

- `docs/NOEMA007_RISK_BASELINE_FRESHNESS.md`
- `README.md`

The evaluator distinguishes `current`, `due`, `overdue` and `unknown`. It uses only a source-declared update interval; missing intervals stay unknown. Retrieval time is not substituted for dataset update time. URLs are not fetched, reuse is not authorized, no hazard threshold is chosen, no alert is sent, and ingestion is always false.

Evidence:
- **FACT:** the joint 2026 UNDRR/WMO/ITU/IFRC report calls for robust observational infrastructure, governance, human oversight, inclusive/multilingual and low-connectivity design, and modular inter-pillar integration.
- **FACT:** OGC API–Features provides geospatial feature discovery/query building blocks; it is not a universal freshness policy.
- **REPRODUCED RESULT:** synthetic tests cover date boundaries, missing metadata, UTC validation, and the non-authorizing licence field.
- **INFERENCE:** metadata-first checks can expose missing update-cycle declarations before sensitive feature data is accessed.
- **HYPOTHESIS:** source-owner-maintained update intervals may reduce unnoticed baseline drift.
- **UNTESTED IDEA:** compare freshness flags against independent GIS/DRR expert audits on permissioned non-sensitive datasets.

### 2. NOEMA-005 — cgroup v2 mount-root resolution

Created [PR #157](https://github.com/maisuradzee/bibmom/pull/157), branch `research/noema005-cgroup-mount-root-resolution-2026-11-27`, final head `37f2d3576faade1c0963c31362698b0c45c11f7b`.

Files:
- `scripts/run_noema005_openmp_timing_diagnostic.py`
- `tests/test_noema005_openmp_timing_diagnostic.py`
- `research/drafts/NOEMA-2026-005-cgroup-mount-root-resolution-2026-11-27.md`

The inline path mapping was extracted into a pure helper and hardened to compare exact path segments, rejecting sibling-prefix, relative, repeated-separator and parent-traversal cases. Mountinfo escaped space/tab/backslash handling is covered.

Evidence:
- **FACT:** mountinfo field 4 is the filesystem root of a mount and field 5 its mount point relative to the process root (Linux man-pages `proc_pid_mountinfo(5)`).
- **FACT:** cgroup v2 resource controllers are hierarchical; ancestor constraints cannot be overridden by descendants (Linux kernel cgroup v2 documentation).
- **REPRODUCED RESULT:** deterministic unit tests exercise the pure path helper.
- **INFERENCE:** segment-aware matching reduces wrong-directory resolution risk.
- **HYPOTHESIS:** this improves provenance reliability in bind-mount/container mount namespaces.
