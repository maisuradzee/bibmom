## Work completed

A local C/OpenMP harness was compiled with GCC 14.2.0 and executed on a KVM-virtualized Linux x86-64 host. The harness compared four serial and four OpenMP reduction strategies on two deterministic binary64 cancellation orders. Each layout contains 36,000,000 elements (288,000,000 input bytes), with one warm-up and five measured repetitions per case. The harness recorded actual OpenMP team size, wall time and process CPU time for requested worker counts 1, 2, 4, 5 and 8.

## Frozen result

- 48 method/layout/worker cases were captured.
- Full Neumaier (sum, correction) state returned the exact integer oracle in 5/5 repetitions for both layouts and all requested worker counts.
- Naive and pairwise variants returned the exact oracle in 0/5 repetitions on these specific inputs.
- long double with LDBL_MANT_DIG=64 passed the triplet order and failed the grouped order.
- Median runtime and process-CPU samples are retained in the raw JSONL artifact. Worker-count timing is non-monotonic; no general speedup or optimal worker count is inferred.

## Environment and limitations

- CPU model: Intel Xeon Platinum 8573C, KVM-virtualized Linux x86-64.
- Visible CPU IDs: 0-4; cgroup quota: 4.0 CPUs.
- Five- and eight-worker cases exceed the quota and are diagnostic oversubscription cases.
- Effective input-scan GiB/s is a bytes/time estimate, not a DRAM hardware counter.
- This is one virtualized environment, not a bare-metal or independent second-device replication.
- Only two synthetic cancellation patterns were tested; no production workload, ARM64 physical host, NUMA/cache counter, energy or independent reviewer was available.
