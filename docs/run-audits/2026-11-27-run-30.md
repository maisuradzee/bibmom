### NOEMA-007 — public source URL metadata hardening

**Research question:** can common credential-bearing URL forms be rejected before source metadata is persisted in a public research record, while retaining ordinary public catalogue selectors?

**Implementation:** [PR #156](https://github.com/maisuradzee/bibmom/pull/156), branch `research/noema007-risk-baseline-freshness-evaluator-2026-11-27`.

The guard now:

- rejects URL user-info credentials;
- parses both `&` and `;` query/fragment separators;
- checks parameter names after up to four percent-decoding passes, catching common double-encoded names;
- rejects known credential-like names, control characters/whitespace, malformed ports and excessive field counts;
- preserves ordinary public catalogue selectors;
- never fetches the URL.

Six synthetic URL-safety test methods cover user-info credentials, encoded and double-encoded secret names, semicolon-delimited parameters, ordinary selectors, invalid ports and whitespace.

**REPRODUCED RESULT:** final head `7c5fd0494fc9bf6f4ddaf5a0ed85cdeda264d85b` passed Quality CI [46013790588](https://github.com/maisuradzee/bibmom/actions/runs/46013790588) and both CPU-thread jobs [46013790782](https://github.com/maisuradzee/bibmom/actions/runs/46013790782).

**FACT:** Python 3.14's `urllib.parse` documentation states that `urlsplit()` does not perform validation. It documents `parse_qsl()`'s `separator` parameter, whose default is `&`; since Python 3.10 a single separator is used by default. NOEMA therefore tests both separators explicitly. Source: https://docs.python.org/3.14/library/urllib.parse.html

**FACT:** Visser et al. (2026), *Temporal characteristics of disaster data: how to avoid misconceptions, misinterpretation, or misuse*, is a peer-reviewed review article in the *International Journal of Disaster Risk Reduction*, volume 142, article 106188, DOI 10.1016/j.ijdrr.2026.106188. It discusses temporal-data reliability and trend-model uncertainty; it does not prescribe a universal freshness interval. Source: https://doi.org/10.1016/j.ijdrr.2026.106188

**Limitations:** this remains a heuristic metadata hygiene guard, not a complete secret scanner or full URL validator. It does not inspect arbitrary string values, every non-standard URL representation, remote redirects or publisher authenticity. No Georgian dataset was ingested or evaluated. PR remains Draft pending independent GIS/DRR, metadata-governance and privacy review.
