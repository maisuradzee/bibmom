**Review finding:** the comparator treated equal opaque IDs (indicator, numerator/denominator definitions, sampling frame, inclusion rule and analytical method) as evidence that the underlying definitions were equal. ### NOEMA-005 / numerical reduction

**Existing parent PR:** [#132](https://github.com/maisuradzee/bibmom/pull/132), Draft, head `b4d150a94d9aebbb1ee6c36e67768a805926a22c`. Exact-head Quality CI [45974913049](https://github.com/maisuradzee/bibmom/actions/runs/45974913049) succeeded. The new hosted batch [45972740197](https://github.com/maisuradzee/bibmom/actions/runs/45972740197) is x86-64 AWS virtual-runner evidence, not physical-device replication.

**Frozen result (not a new benchmark in this cycle):** full Neumaier state was correctly rounded in 48/48 measured runs in each runtime; median wall-time speedup was 0.7541x (GIL-enabled) and 0.7021x (free-threaded). The result does not support a speedup claim. CPU-time/wall-time ratio is not wall-time speedup.

**Review finding:** the original raw-report reproducer checked 48 rows and 16 rows per method, but did not validate the complete 2-layout × 4-worker × 2-partition matrix or reject duplicate/missing cells. It also needed stronger numeric/range and timing-sample consistency checks. The original artifact ZIP SHA is recorded from acquisition, but the committed reproducer only re-hashes extracted report bytes; the original ZIP bytes are not committed and its archive SHA cannot be replayed by `--check`.

**Follow-up:** [#133 — verifier hardening](https://github.com/maisuradzee/bibmom/pull/133), Draft, final head `9c8e7111526a67fdfc8b0ace7dced93e10d93fd1`, targets PR #132's branch. It now validates the exact 2-layout × 4-worker × 2-partition matrix for each method, rejects duplicate/incomplete cells, validates positive finite speedups, integer accuracy and memory fields, native thread IDs, raw timing medians, CPU/wall ratios and threshold flags.

- The first two verifier attempts failed because the initial matrix model omitted the two input layouts. The model was corrected; this failure is preserved in CI history, not hidden.
- Final exact-head Quality CI [45980689146](https://github.com/maisuradzee/bibmom/actions/runs/45980689146): SUCCESS.
- Focused Run 23 verifier tests: 14 passed; full suite: 471 passed.

### NOEMA-007 / warning-to-action readiness

**Existing PR:** [#130](https://github.com/maisuradzee/bibmom/pull/130), Draft, head `46ce488a425da256345c41e8eac1a1d6138cbed0`; exact-head Quality CI [45976114767](https://github.com/maisuradzee/bibmom/actions/runs/45976114767) succeeded. Its base is the pre-Run-23 main snapshot and it now needs rebase/update plus new exact-head CI.

**Review finding:** the new timely-receipt threshold is checked as a non-negative integer, but not bounded by the available lead window between warning issue time and action deadline. A threshold larger than that window could make “timely” impossible by construction. A follow-up should reject this case (or explicitly model a different deadline policy) and test equality, overrun and zero-window behavior. No code change or field-data claim is made in this run.

The protocol remains a proposed aggregate-only survey contract. Respondent recall is not device-verified receipt; endpoint delivery is not a person-level read; no authorized Georgian event data or field partner was obtained.
