# NOEMA Run 45 — INFRA-001 CI recovery hardening

- **Reviewed Main base:** `f5a7d57d70705f2378a78e76e23013e6fb112835` (2026-11-28).
- **Engineering branch:** `engineering/ci-recovery-required-step-gate-2026-11-28`; changes are proposed and not merged.
- **Prior review findings addressed in this proposal:** (1) observed step outcomes alone cannot detect a deleted/renamed required validation step; (2) the earlier recovery proposal promoted narrative URLs into Sources and did not bound URL/query/fragment parsing.
- **Required-step gate:** added `data/ci-required-step-ids.json`, its closed schema, and `scripts/validate_ci_workflow_contract.py`. The workflow assigns stable IDs to every step, continues after independent validation failures, and ends with an unconditional aggregate gate. Missing, failed, skipped, cancelled or unknown required outcomes fail the job. Checkout and dependency installation remain fail-fast prerequisites.
- **Source provenance:** recovery now normalizes only known date/status labels and heading aliases. It never promotes a URL from narrative/next-step text into Sources. Only explicit Sources-section URLs are checked. URL length is capped at 2,048 characters; query and fragment field counts are capped at 32 and 16; credential-like parameter names are checked after bounded percent-decoding; user-info, invalid ports and non-public host literals are rejected.
- **Diagnostic hygiene:** unsafe URL values are not included in report entries. The generated diff uses zero context and contains only changed presentation lines. Repairs remain in the ephemeral CI workspace and are not pushed.
- **Tests added:** deterministic cases for required-step omission/failure/skipped/unknown outcomes, manifest/workflow parity, URL-length and field-count boundaries, encoded credential names, private hosts, user-info, invalid ports and no URL promotion.
- **Validation status:** exact-head CI is pending. No test count, mergeability or deployment success is claimed yet.
- **Review boundary:** this is a self-authored engineering proposal, not an independent security review. URL validation is syntactic only; it does not fetch URLs, resolve DNS, authenticate publishers or provide SSRF protection.
