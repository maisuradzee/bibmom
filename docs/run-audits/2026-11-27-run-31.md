## Work completed

### INFRA-001 — non-finite restore measurement bypass

**FACT:** Python 3.14's official JSON documentation says the default decoder accepts `NaN`, `Infinity` and `-Infinity` as Python floats even though these tokens are outside the JSON specification: https://docs.python.org/3.14/library/json.html

**REPRODUCED RESULT:** a local minimal test with the repository's JSON Schema dependency accepted NaN and positive infinity for a number field with `minimum: 0`. In the previous evaluator, a NaN measured duration/data-loss value makes the `>` comparison false; an infinite RPO/RTO target can also suppress an overrun. This is a synthetic code-path finding, not a production exploit or recovery test.

**Implementation:** [PR #163](https://github.com/maisuradzee/bibmom/pull/163), branch `infra/restore-attestation-finite-measurements-2026-11-27`.

- Adds runtime `math.isfinite` checks for restore duration, data loss and non-null RPO/RTO targets.
- Explicitly rejects booleans as numeric measurements.
- Adds synthetic NaN and positive-infinity regression cases.
- Documents the boundary in `docs/RESTORE_ATTESTATION_GATE.md`.

**Exact-head validation:** head `23d3f993041fb52cd3e3ecdcf065200c2c96ff12`; Quality CI [46024546433](https://github.com/maisuradzee/bibmom/actions/runs/46024546433) — SUCCESS. All 34 workflow steps succeeded, including draft completeness, source/portfolio checks, frozen reproductions, backup/restore CLI, 458 Python tests, public site build and publication-boundary checks.

**Limitations:** no provider, backup object, signing key, external high-water authority, production database or clean-host restore was used. This closes one local evaluator edge only; it does not establish production disaster-recovery readiness.
