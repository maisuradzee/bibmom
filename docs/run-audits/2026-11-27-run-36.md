### NOEMA-INFRA-001 — provenance and restore

**Work:** added strict bounded serialized-input handling in Draft PR #191.

New API:
- load_restore_attestation_bytes()
- evaluate_restore_attestation_bytes()

The bytes boundary requires exact UTF-8, caps input at 1 MiB, rejects duplicate JSON object keys recursively, rejects NaN/Infinity/-Infinity tokens and requires an object root before schema/completeness evaluation. Six synthetic regression tests cover valid bytes, duplicate keys, non-standard constants, exponent overflow to infinity, invalid UTF-8, non-object roots, size limit and wrong input type.

This is parser hardening only. It does not authenticate evidence signatures, establish issuer-key trust, query provider storage, prove clean-host recovery or implement production/offsite backup.
