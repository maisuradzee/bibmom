A deterministic audit of the frozen native OpenMP raw report found nine of 80 paired OpenMP process-CPU/wall-time samples above 4.05, affecting five of 16 OpenMP cases. The report records four effective CPUs (cpuset 0-3); the maximum ratio is 13.287713.

The Linux manual states that CLOCK_PROCESS_CPUTIME_ID includes CPU time from all process threads. Linux cgroup v2 documentation states that cpuset.cpus.effective lists CPUs available to tasks in that cgroup. The mismatch is treated as a timing/provenance anomaly requiring a controlled rerun, not as a proven code defect.
