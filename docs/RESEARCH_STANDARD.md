# NOEMA — კვლევითი და სარედაქციო სტანდარტი

## მიზანი

NOEMA-ს მიზანია შეინახოს არა მხოლოდ საინტერესო პასუხები, არამედ მტკიცებულებების წარმომავლობა, გამოყენებული მეთოდი, გაურკვევლობა და ის პირობებიც, რომლებშიც შედეგი შეიძლება მცდარი აღმოჩნდეს.

## 1. მტკიცებების კლასიფიკაცია

ყოველ კვლევაში მტკიცებები უნდა დაიყოს შემდეგ კატეგორიებად:

- **FACT — დადასტურებული ფაქტი:** პირდაპირ მხარდაჭერილია მითითებული პირველადი წყაროთი, მონაცემით ან დოკუმენტით.
- **REPRODUCED RESULT — ხელახლა მიღებული შედეგი:** გამოთვლილია კონკრეტული მონაცემთა snapshot-იდან და შენახული კოდით; მითითებულია მონაცემთა ვერსია და hash.
- **INFERENCE — დასკვნა:** ლოგიკურად გამომდინარეობს ფაქტებისა და შედეგებისგან, მაგრამ თავად პირდაპირი დაკვირვება არ არის.
- **HYPOTHESIS — ჰიპოთეზა:** შემოწმებადი მოსაზრება, რომელიც შეიძლება უარყოფილი ან შესწორებული იყოს.
- **UNTESTED IDEA — შეუმოწმებელი იდეა:** შესაძლო მიმართულება, რომელსაც ჯერ მტკიცებულება არ ამყარებს.

არ შეიძლება ჰიპოთეზის ან დასკვნის ფაქტად წარმოდგენა.

## 2. წყაროების პრიორიტეტი

1. პირველადი სამეცნიერო სტატია, ოფიციალური მონაცემთა ბაზა, პირველწყარო დოკუმენტი ან ავტორის მიერ გამოქვეყნებული მონაცემი.
2. რეცენზირებული დამოუკიდებელი კვლევა და მეთოდოლოგიური კრიტიკა.
3. უნივერსიტეტის, მუზეუმის, სამეცნიერო ინსტიტუტის ან სახელმწიფო უწყების ოფიციალური მასალა.
4. მაღალი სანდოობის სამეცნიერო/ტექნიკური მიმოხილვა.
5. მეორადი მედია და სხვა არასამეცნიერო წყარო — მხოლოდ კონტექსტისთვის; არა როგორც ერთადერთი საფუძველი მნიშვნელოვანი მტკიცებისთვის.

წყაროს სრული ციტირება, ავტორი/ორგანიზაცია, გამოცემის თარიღი, ვერსია საჭიროების შემთხვევაში, DOI/URL და წვდომის თარიღი უნდა ჩაიწეროს. თუ გამოცემის თარიღი წყაროში მითითებული არ არის, გამოიყენეთ კატალოგში publication_date=undated და publication_note-ში პირდაპირ აღნიშნეთ, რომ თარიღი წყაროში მითითებული არ არის; წვდომის თარიღი გამოცემის თარიღად არ ჩაანაცვლოთ. თუ წყაროები ერთმანეთს ეწინააღმდეგება, ეს განსხვავება ანგარიშში უნდა გამოჩნდეს.

## 3. მონაცემთა წარმომავლობა და გამეორებადობა

თითოეული რაოდენობრივი კვლევა ინახავს:

- მონაცემთა წყაროს და ზუსტ ვერსიას/commit-ს;
- გამოყენებული ფაილების SHA-256 ან Git blob hash-ს;
- მონაცემის ლიცენზიას და შეზღუდვებს;
- დამუშავების წესებს;
- სკრიპტს, პარამეტრებსა და შემთხვევითი seed-ს;
- შედეგების JSON/CSV snapshot-ს;
- დამოუკიდებელი გამეორების სტატუსს.

თუ მონაცემის ნაწილი ხელმისაწვდომი არ არის ან ლიცენზია გამოყენებას ზღუდავს, ეს პირდაპირ უნდა ითქვას. დაუშვებელია დაკარგული ან მიუწვდომელი მონაცემის გამოგონება.

## 4. ექსპერიმენტის მინიმალური წესები

- კვლევის კითხვა და წარმატების კრიტერიუმი განისაზღვროს მონაცემების ნახვამდე, სადაც ეს შესაძლებელია.
- სასწავლო, საკალიბრაციო და სატესტო მონაცემები მკაფიოდ გაიმიჯნოს.
- ჯგუფური მონაცემებისთვის გამოიყენოს ჯგუფის მიხედვით გამიჯვნა, რათა ერთი და იმავე ობიექტის/საიტის ფრაგმენტები ორივე მხარეს არ მოხვდეს.
- შეფასდეს მარტივი baseline; კომპლექსურმა მოდელმა უნდა აჯობოს მას.
- ჩაიწეროს ყველა გამორიცხვა და უცნობი მნიშვნელობა.
- უარყოფითი შედეგიც ჩაითვალოს კვლევის შედეგებად.
- ერთი პოსტ-ჰოკ ზღურბლის/მოდელის შერჩევა არ ჩაითვალოს დამოუკიდებელ პროგნოზულ მტკიცებულებად.

## 5. AI-ის გამოყენების საზღვრები

AI-ს შეუძლია:
- მონაცემების ფორმატის შემოწმება;
- ლექსიკონთან კოდების შედარება;
- განმეორებადი გამოთვლები;
- შესაძლო შეცდომების/გაურკვევლობების მონიშვნა;
- მკაფიოდ განსაზღვრული კლასიფიკაციის ამოცანის შესრულება.

AI-მ არ უნდა:
- მიაწეროს არქეოლოგიურ ნიშანს მნიშვნელობა მტკიცებულების გარეშე;
- საკუთარი გენერირებული პასუხი ჩათვალოს ეტალონურ ეტიკეტად;
- ჩუმად წაშალოს უცნობი სიმბოლო ან მონაცემი;
- წარმოადგინოს მოდელის თავდაჯერებულობა ისტორიული სიზუსტის გარანტიად.

თუ გამოსახულების გამოყენების უფლება, მონაცემის საკმარისი რაოდენობა ან ადამიანის ეტალონური შეფასება არ არსებობს, ვიზუალური მოდელის შედეგი არ უნდა გამოცხადდეს.

## 6. კვლევის სტატუსები

- `draft` — სამუშაო ვერსია; საიტის საჯარო არქივში არ ჩანს.
- `review` — წყაროები და მეთოდი შემოწმებულია, მაგრამ სარედაქციო/დამოუკიდებელი განხილვა ან სხვა მოთხოვნა დარჩენილია; საჯარო გამოქვეყნება ჯერ არ შეიძლება.
- `preliminary` — წინასწარი, საჯარო კვლევითი ანგარიში `research/preprints/`-ში. გვერდზე სავალდებულოა ხილული გაფრთხილება, რომ შედეგი ჯერ არ არის დამოუკიდებლად რეცენზირებული და ყველა შეზღუდვა/დაუსრულებელი შემოწმება უნდა ჩანდეს.
- `published` — გავლილია ყველა გამოქვეყნების კრიტერიუმი, კვლევის ფაილი დევს `research/published/`-ში, ხოლო ინდექსში სწორადაა დამატებული.

მხოლოდ GitHub-ში საჯაროდ არსებული დრაფტი ვებსაიტზე გამოქვეყნებულ კვლევად არ ითვლება.

## 7. გამოქვეყნების საკონტროლო სია

კვლევა შეიძლება გადავიდეს `preliminary` სტატუსში მხოლოდ თუ საკვლევი კითხვა, ძირითადი წყაროები და მეთოდი აღწერილია; მონაცემები და შედეგები არ არის გამოგონილი; შეზღუდვები/გაურკვევლობა თვალსაჩინოა; კონფიდენციალური ან შეუმოწმებელი პირადი მონაცემები არ ქვეყნდება; და CI-ის build/ვალიდაცია წარმატებით სრულდება. `preliminary` არ ნიშნავს peer-reviewed ან საბოლოო შედეგს.

კვლევა შეიძლება გადავიდეს `published` სტატუსში მხოლოდ თუ:

- [ ] საკვლევი კითხვა და მეთოდი აღწერილია;
- [ ] მნიშვნელოვანი მტკიცებები წყაროებითაა მხარდაჭერილი;
- [ ] ფაქტები, დასკვნები, ჰიპოთეზები და შეუმოწმებელი იდეები გამიჯნულია;
- [ ] მონაცემთა ვერსია და წყაროები აღრიცხულია;
- [ ] გამოთვლადი შედეგი ხელახლა მიიღება შენახული კოდით;
- [ ] მინიმუმ ერთი დამოუკიდებელი ან ალტერნატიული შემოწმება შესრულებულია;
- [ ] შეზღუდვები, გაურკვევლობა, ეთიკა და უსაფრთხოება აღწერილია;
- [ ] ლიცენზია და ვიზუალების გამოყენების უფლება შემოწმებულია;
- [ ] CI წარმატებით დასრულდა;
- [ ] შესაბამისი პასუხისმგებელი რეცენზია/სარედაქციო განხილვა დასრულდა.

`preliminary` ჩანაწერი ინახება `research/preprints/`-ში და შეიძლება შევიდეს საჯარო კატალოგში მკაფიო სტატუსით. `draft` და `review` ჩანაწერები არ შედის Pages არტეფაქტში. `published` ჩანაწერი ინახება `research/published/`-ში.

## 8. შეცდომის გასწორება

თუ ახალი მტკიცებულება ძველ დასკვნას ასუსტებს ან უარყოფს:

1. თავდაპირველი ფაილი არ უნდა წაიშალოს ჩუმად;
2. განახლებული ვერსია უნდა მიუთითებდეს, რა შეიცვალა და რატომ;
3. README ან კვლევის ინდექსი უნდა ასახავდეს მიმდინარე სტატუსს;
4. ძველი შედეგის შეცდომა მკაფიოდ უნდა იყოს აღწერილი;
5. ისტორია Git commit-ებში უნდა დარჩეს.

## 9. მიმდინარე პროექტის გადაწყვეტილება

NOEMA-ს პირველი კვლევები ინახება `research/drafts/`-ში. საჯარო GitHub საცავი და GitHub Pages სხვადასხვა ზედაპირია: Pages build იღებს მხოლოდ მთავარ სტატიკურ ფაილებს, `data/research.json`-ს და `research/published/`-ს. დრაფტები საიტის არტეფაქტში არ უნდა მოხვდეს.

## 10. საჯარო წყაროს URL-ების უსაფრთხოება

საჯარო კვლევით ჩანაწერში ჩაწერილი URL შეიძლება GitHub branch-სა და PR-ში საჯაროდ გამოჩნდეს. ამიტომ წყაროს URL-ის მიღებამდე:

- მოითხოვე აბსოლუტური HTTPS URL და ვალიდური hostname/port;
- უარყავი user-info credentials (`user:password@host`);
- უარყავი credential-ის მსგავსი query ან fragment პარამეტრის სახელები (მაგ. token, api_key, secret, password, signature), მათ შორის bounded percent-decoding-ის შემდეგ;
- შეზღუდე URL-ის სიგრძე და query/fragment field-ების რაოდენობა;
- არასოდეს ჩაწერო URL-ში access token, signed URL secret, API key ან სხვა bearer credential.

ეს შემოწმება არის საჯარო metadata-ის ჰიგიენა და არა წყაროს ავთენტიფიკაცია, ხელმოწერის შემოწმება ან SSRF-ისგან დაცვა. URL-ის ვალიდაცია თავისთავად არ ნიშნავს, რომ მისამართი უნდა ჩაიტვირთოს. URL-ების ჩამოტვირთვა/მიღება უნდა იყოს ცალკე, მკაფიოდ ნებადართული და აუდიტირებადი პროცესი; ბინარული ან ავტორიზებული მონაცემი უნდა დარჩეს კერძო არხში, თუ საჯარო ხელახალი გამოყენების უფლება დადასტურებული არ არის.


## 11. მტკიცებულების ეტიკეტების ერთიანი ლექსიკონი

ყველა კვლევით ჩანაწერსა და კატალოგში მნიშვნელოვანი მტკიცებები უნდა გაიმიჯნოს შემდეგი ეტიკეტებით:

- **FACT** — მტკიცება, რომელიც პირდაპირ მხარდაჭერილია იდენტიფიცირებადი პირველადი წყაროთი, ოფიციალური მონაცემით ან რეცენზირებული ნაშრომით. მიუთითეთ წყაროს ვერსია/თარიღი, ფარგლები და შეზღუდვა. პრესრელიზი ან მეორადი მიმოხილვა არ აქცევს მის ყველა ინტერპრეტაციას ფაქტად.
- **REPRODUCED RESULT** — შედეგი, რომელიც ხელახლა იქნა მიღებული აღწერილი კოდითა და გაყინული შეყვანით. აუცილებელია კოდის commit, ბრძანება, runtime/არქიტექტურა, input/output digest, repetitions და tolerance. თუ სხვა გუნდი/მოწყობილობა დამოუკიდებლად არ იმეორებს, არ გამოიყენოთ ტერმინი independent replication.
- **INFERENCE** — ლოგიკური ინტერპრეტაცია FACT-ებიდან ან REPRODUCED RESULT-ებიდან. ჩამოთვალეთ დაშვებები, გაურკვევლობა და მინიმუმ ერთი კონკურენტი ახსნა.
- **HYPOTHESIS** — შემოწმებადი და უარყოფადი მტკიცება, რომლისთვისაც საჭირო ტესტი ჯერ არ დასრულებულა.
- **UNTESTED IDEA** — შესაძლო გადაწყვეტა ან ექსპერიმენტი, რომლის განხორციელებადობა/ეფექტი ჯერ არ შემოწმებულა.

წესები:
1. ერთი წინადადება ერთ ძირითად მტკიცებას უნდა შეიცავდეს; შერეული ფაქტი/ვარაუდი დაყავით ცალკე წინადადებებად.
2. REPRODUCED RESULT არ მიენიჭოს მხოლოდ იმიტომ, რომ workflow წარმატებით დასრულდა. უნდა არსებობდეს გაყინული input/result, მეთოდი და ხელახლა გაშვებადი reproduction.
3. CPU/wall concurrency არ არის wall-time speedup; correlation არ არის causation; planned sample count არ არის collected sample count; historical aggregate არ არის current population exposure.
4. უცნობი მნიშვნელი, თარიღი, ერთეული, detection limit ან reuse right მკაფიოდ აღინიშნოს როგორც უცნობი.
5. preliminary მოითხოვს აღწერილ მეთოდს, წყაროებსა და შეზღუდვებს. published მოითხოვს დამოუკიდებელ რეცენზიას/სარედაქციო განხილვასა და publication checklist-ის ყველა პუნქტს.
